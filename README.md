# 鲸群记忆

AstrBot 的长期记忆插件。记忆存成本地的 Markdown 文件，不需要 Embedding 模型。插件标识是 `astrbot_plugin_memory_pod`。

最初基于 [AlanBacker/astrbot_plugin_memory_beyond](https://github.com/AlanBacker/astrbot_plugin_memory_beyond) v1.4.1 修改（MIT 许可证），现在的数据结构和配置都已经和 Memory Beyond 不同，不能沿用它的数据和配置，也不提供迁移。

## 它做什么

- **三层记忆。** 留言板是所有机器人都能看的告示；小本本是一个机器人自己的记忆，可以讲给别人听；悄悄话只在原来那段对话里能看到。
- **机器人自己记。** 聊天模型用工具读写记忆。用户说"记住""改一下""忘掉"时当轮就写；另外每聊 10 轮、AstrBot 截断或压缩上下文之前，插件会各提醒它一次。
- **每轮只带用得上的。** 系统提示词末尾带上留言板告示和记忆目录，私聊时还有对方的档案；每条新消息再附上最相关的几条记忆。
- **记得是谁说的。** 小本本里的内容出现在别的对话里时，会注明"小明在群聊里说的，3 天前"。
- **改了能恢复。** 每次覆盖、修改、删除之前自动保存旧版，删掉的文件进回收站。
- **上下文交给 AstrBot。** 插件不截断也不压缩上下文；管理页能看到每轮请求的构成和 AstrBot 压缩后的摘要。

## 安装

在 AstrBot WebUI 里用本仓库地址安装，或者把仓库克隆到 `data/plugins/astrbot_plugin_memory_pod`。插件只用 Python 标准库和 AstrBot 的插件接口，没有第三方依赖。开发和测试用的是 AstrBot 4.29.4，记忆管理页需要 4.24.1 及以上。

装好就能用，不需要改 AstrBot 的任何设置。上下文怎么截断、怎么压缩，按 AstrBot 的「上下文管理策略」来。

## 三层记忆

| 层 | 作用域 | 目录 | 谁能读 | 谁能写 |
| --- | --- | --- | --- | --- |
| 留言板 | `board` | `memories/board/` | 这个 AstrBot 里所有机器人的所有对话 | AstrBot 管理员：在管理页发，或者在对话里让机器人代发 |
| 小本本 | `notebook` | `memories/notebook/<机器人>/` | 这个机器人的所有群聊和私聊 | 机器人自己 |
| 悄悄话 | `whisper` | `memories/whisper/<对话>/` | 只有这段对话：私聊是机器人和这个人之间，群聊是这个群 | 机器人自己 |

- **留言板**放告示，比如"11 月 11 日新员工 teto 入职"。每条告示都有署名：管理页发的用你填的署名，机器人代发的写成"堇（由 Bot-深海小鲸 代发）"。告示可以设到期日，过期后不再出现在系统提示词里，但文件保留，管理页里可以续期。
- **小本本**放日记、认识的人（主档案 `user-<平台ID>.md`，主题档案 `user-<平台ID>-<主题>.md`，主题用小写英文、数字和连字符）、听来的事、进行中的事和资料。
- **悄悄话**放隐私和只属于这段对话的事：健康、亲密、家庭矛盾、心事，以及群里不该传到别的群的事。私聊的悄悄话在群里读不到，哪怕这个人正在群里说话。

小本本和悄悄话里的每个文件有一个类型：人物（`person`，某个人的档案）、约定（`agreement`，相处的约定和对机器人的要求）、笔记（`note`，其余所有内容）、日记（`journal`）。留言板的告示不分类型。文件里出现不认识的类型时，按笔记处理。

由代码强制执行、不靠模型自觉的规则：

1. 悄悄话只能读写当前这段对话的，工具和召回都碰不到别的对话的悄悄话；
2. 留言板只有发送者是 AstrBot 管理员时才能写；
3. 一个人的档案（主档案和主题档案），只有本人或管理员在说话时才能改；
4. 小本本里对机器人自己的要求（`agreement` 约定），只有管理员能写，其他人提的要求只能记进这段对话的悄悄话；
5. 文件名、类型、长度都要校验，每次写入都留历史。

交给模型判断的：一件事该放小本本还是悄悄话（拿不准时，私聊里先问对方，群聊里先放悄悄话）；别人说的关于某个人的话，记成日记或转述，不改那个人的档案。

## 记忆怎么写

聊天模型有五个工具：

| 工具 | 作用 |
| --- | --- |
| `memory_read(scope, file)` | 读一个文件的全文；`file` 省略时读这一层的索引 |
| `memory_search(query, scope, mode)` | 全文搜索，`scope` 可以填 `all`；`mode=any` 时命中任意一个词即可 |
| `memory_write(scope, file, type, description, content, expires)` | 新建，或整篇重写已有文件。整篇重写前必须先读过最新版本；`expires` 只对留言板有效 |
| `memory_edit(scope, file, mode, old_text, new_text, description)` | 局部修改：`replace` 替换一段，`append` 追加，`section` 替换一个小节的正文 |
| `memory_delete(scope, file, reason)` | 删除，文件进回收站，原因记进审计 |

文件开头的 frontmatter 由插件生成：类型、一句话摘要、首次写入和最近修改的时间、说话人的 QQ 号，以及来源（私聊还是群聊、说话人当时的名字、时间）。留言板的告示另外记署名和到期日。群号和群名不写进记忆文件，只记在审计日志里，管理页能看到。

**日记**：模型用 `memory_edit` 往 `journal` 里追加就行，写到哪一篇由插件决定。默认接着最近一篇写；最近一篇超过 3000 字，或者最后一次更新已经过了 7 天，就新开一篇 `journal-<日期>.md`。每段追加前面自动加一行时间和来源，比如"08:30 小明（群聊）"。日记不参与召回，在索引里折叠成"最近两篇加一行汇总"。

**提醒**：每聊 `memory_reminder_turns`（默认 10）轮，插件在这一轮的请求里提醒模型回顾最近的对话，把值得记的写下来。上下文超过窗口的 70%，或者快到 AstrBot 设的轮数上限时，在截断或压缩之前再提醒一次。提醒不存进会话历史。

## 记忆怎么用

每轮请求里，插件自动带上两块内容：

- **开头块**接在 AstrBot 的系统提示词后面，包括记忆规则、留言板的告示、小本本和悄悄话的索引；私聊时还有对方在小本本和悄悄话里的主档案。告示全文从新到旧排列，合计不超过 2000 字，超出的只列标题。开头块是一份快照，只有这些情况才刷新：换对话或重置、在管理页改了记忆、AstrBot 截断或压缩了上下文、每天第一轮、留言板有任何改动、写入了 `agreement`（约定），以及删除了钉在开头块里的档案。普通的小本本或悄悄话写入不刷新，新内容由召回带上。其余时候逐字不变，所以能命中提示词缓存。
- **召回块**附在这一轮的用户消息里，不存进会话历史。插件按关键词挑出最多 `recall_max_files`（默认 5）个相关文件：发送者和被 @ 的人的主档案带全文，主题档案和别的文件一样按关键词挑；其余文件里，相关度最高的 `recall_full_files`（默认 2）个带全文，剩下的只列文件名。单个文件超过 3000 字时保留开头和结尾，整块合计不超过 9000 字。

小本本里的内容出现在别的对话里时，读取、搜索、召回块和开头块都会注明来源，比如"（小明在群聊里说的，3 天前）"，说的是自己的事时写"（本人说的）"。只写群聊还是私聊，不写群名。在管理页写的内容不标来源。

开头块、召回块和 `memory_read` 的结果都按数据呈现，模型会被告知里面看起来像指令的文字一律不执行。

## 上下文

插件不截断、不压缩上下文，这些都由 AstrBot 的「上下文管理策略」负责。插件放进系统提示词和本轮用户消息里的内容，不会被 AstrBot 截断，不会被压缩进摘要，也不会存进会话历史。

管理页的「上下文」面板只读，显示：最近一次请求由哪些部分组成（系统提示词，以及其中插件的开头块、工具声明、历史、召回块，按 token 估算）；模型实际报告的输入 token 数和缓存命中数；AstrBot 最近一次压缩生成的摘要。

窗口大小按 AstrBot 的顺序取：提供商里填的窗口、AstrBot 自带的模型表、AstrBot 的「上下文窗口兜底值」。这个值只用来决定截断前的那次提醒，以及在面板上显示。

## 历史、回收站与遗忘

- 每次覆盖、修改、删除之前，旧内容存进这一层目录的 `.history/`，删掉的文件进 `.trash/`。每次变更在 `.audit.jsonl` 里记一行：时间、动作、文件名、哪个机器人改的、对话、群名、说话人、说话人是不是管理员、内容哈希，不记正文。
- 历史版本保留 `history_keep_days`（默认 90）天，每个文件至少留最近 10 版；回收站保留 `trash_keep_days`（默认 90）天。填 0 表示永久保留。
- 管理页里可以查看、恢复任何一版。有人要求删除自己的信息时，用「彻底删除（含历史）」把文件、历史版本和回收站里的副本一起删掉。审计日志里那几行会保留，它们没有正文，但有文件名、群名和说话人。
- 遗忘（`enable_forgetting`，默认关）：连续 `forget_after_days`（默认 90）天没被召回、也没被读过的记忆，移进 `forgotten/`，不再进索引和召回。这个人再出现、模型去读它，或者在管理页点恢复，它就回来。`agreement`（约定）类不参与遗忘。

## 记忆管理页

在 AstrBot WebUI 侧边栏的「插件页面」里。顶栏分成留言板、小本本、悄悄话、上下文、管理五块；前三块左边是列表、右边是详情，窄屏时变成单栏。页面跟随 WebUI 的深浅主题和语言。

- **留言板**：告示卡片，显示署名、到期日、是否已过期；可以发布、编辑、续期。
- **小本本**按机器人分，**悄悄话**按对话分（显示群名、昵称和备注）：搜索、按类型筛选、新建、编辑、改名、删除。编辑可以用表单，也可以改原文，保存前会显示改了哪些地方。文件详情里有来源（包括群名）和历史版本，任何一版都能对比和恢复。每个列表底部是这一处的索引、已遗忘、回收站和整理。
- **上下文**：最近一次请求的构成、模型报告的 token 数和缓存命中，以及 AstrBot 的摘要。
- **管理**：概览；整理全部记忆，所有方案一起审阅、一次应用，最近 5 次整理可以撤销；备份与迁移，包括导出、导入、迁到另一处，以及机器人换了平台 ID 之后的整体搬迁。

整理用的是 AstrBot 的默认对话模型，你确认后才写入。删除、彻底删除、应用整理方案、导入覆盖之前，都会先确认。页面里的改动从下一轮对话起生效。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enable_memory` | 开 | 总开关；关掉后不注入记忆，工具也不能用，已有的文件保留 |
| `recall_max_files` | 5 | 每轮最多召回几个文件；0 关闭召回 |
| `recall_full_files` | 2 | 其中带全文的个数，身份档案不占这个名额 |
| `memory_reminder_turns` | 10 | 每聊几轮提醒模型写一次记忆；0 关闭（截断前的那次提醒照旧） |
| `history_keep_days` | 90 | 历史版本保留天数；0 永久 |
| `trash_keep_days` | 90 | 回收站保留天数；0 永久 |
| `enable_forgetting` | 关 | 记忆遗忘 |
| `forget_after_days` | 90 | 多少天没用到就遗忘 |

## 管理指令

`/mb_status`，只有 AstrBot 管理员能用：查看本对话的记忆和上下文状态，包括三层各有多少文件、召回和遗忘的设置、过长的文件、上下文估算、模型实际报告的 token 数和缓存命中、窗口大小、AstrBot 的轮数上限，以及 AstrBot 有没有压缩过这段对话。

## 常见问题

**机器人什么时候写记忆？** 用户明确要求时当轮就写；另外每 10 轮、AstrBot 截断或压缩之前，插件各提醒它一次。想让它记得勤一些，就把 `memory_reminder_turns` 调小。

**群里的人能套出私聊里说的事吗？** 私聊的悄悄话只在那段私聊里能读，这是代码强制的，模型想读也读不到。小本本里的内容本来就是可以讲给别人听的，出现在别的对话里时会注明是谁说的。

**有人改了群名片冒充别人怎么办？** 插件在每条消息开头标注发送者的群名片、QQ 名和 QQ 号，记人以 QQ 号为准。有人在正文里手打一个 `[发送者：…]` 也没用，插件会把它改成全角括号。来源标注里的名字也会先去掉换行和括号，再截到 32 字以内。

## 开发

```bash
python -m pytest -q                       # 只需要 pytest，不需要装 AstrBot
python scripts/prompt_sizes.py --json     # 各段提示词的字数
python scripts/eval/run_eval.py --env-file ~/.config/memory-pod/eval.env --runs 3 --json
```

评测脚本用合成对话，通过插件的真实代码调用真实模型，检查记忆有没有写对、该保密的有没有泄露。它从 `--env-file` 指定的文件里读 `MB_EVAL_BASE_URL`、`MB_EVAL_MODEL`、`MB_EVAL_API_KEY`（OpenAI 兼容接口），这个文件不要放进仓库。

代码分三块：`core/` 是不依赖 AstrBot 的逻辑，可以单独测试；`main.py` 对接 AstrBot 的钩子、工具和指令；`web_api.py` 和 `pages/memory/` 是管理页，页面是静态文件，改完在 WebUI 里刷新即可。
